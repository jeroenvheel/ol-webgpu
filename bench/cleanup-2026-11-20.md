# Performance before and after the cleanup (2026-11-20)

Compares `main` at `fd2e0ee` (0.1.0-beta.3) with the cleanup commit `0185a20`
on the `simplify` branch. Same machine, same session, wasm built from each
branch's own sources.

- Machine: AMD Radeon R9 200 Series, D3D11, Playwright Chromium, 1100×900 map.
- `npm run bench -- --layers=webgl2,webgpu`, two runs per branch, both shown.
- Labels: `examples/labels.html` with `window.__measure()`, one run per branch.
- Milliseconds, lower is better. Runs vary by a few percent.

## Result

No measurable change in frame time or time to first render. The hit index
builds about 5% faster for lines and 7% faster for polygons, and polygon
tessellation is 3% faster. Decluttering a frame went from about 0.45 ms to
about 0.33 ms.

The two larger savings of the cleanup are not exercised by these runs: the
glyph atlas is no longer uploaded on every frame of a layout in progress, and
the picker keeps its measured sizes after a pan instead of measuring again.

## Second round: single-copy worker build and restructurings

Measured after the changes that followed `0185a20`: the worker copies each
instruction array into wasm once and builds the index before tessellating,
point instances go back as the array they came in, the index query reuses its
working memory, and the TypeScript restructurings (readiness set in one
place, deferred destroy of WebGPU resources, one surface spec, a frame plan
shared by both backends). Same machine and method; "before" is `main` as
above, two runs each.

### Result

Time to first render for 1M points on WebGL2 went from about 920 ms to about
857 ms (7%), and for 200k lines on WebGPU from about 915 ms to about 877 ms
(4%). Everything else is within the run-to-run variation: frame times, picks,
polygons, and points on WebGPU, where the two runs were 1094 and 1163 ms
against 1126 and 1117 ms before.
